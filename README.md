# FreeDisplay

> **Free & open-source alternative to [BetterDisplay](https://github.com/waydabber/BetterDisplay)** — all the core display management features, zero cost.

BetterDisplay is a great app, but its best features are locked behind a paid Pro license. FreeDisplay implements the most essential BetterDisplay features as a completely free, open-source macOS menu bar app.

> **About this fork:** FreeDisplay was created by **MingJie Ji ([@huberdf](https://github.com/huberdf))** — original repository: [huberdf/FreeDisplay](https://github.com/huberdf/FreeDisplay). This fork by [@yb1997](https://github.com/yb1997) adds the fixes and improvements listed under [Changes in this fork](#changes-in-this-fork). All credit for the original app goes to its author.

## Changes in this fork

Fixes and improvements on top of the original project:

**Fixes**
- **144Hz lost after enabling HiDPI** — the built-in *HiDPI Mode* preset picked the largest HiDPI mode even when it only runs at 60Hz (e.g. 2560×1440 HiDPI needs a 5K backing that external displays can only drive at 60Hz). It now picks the largest HiDPI mode that still runs at the display's top refresh rate (e.g. 2304×1296 HiDPI @ 144Hz), and re-applying a preset now also corrects a wrong refresh rate.
- **Color Profile showed "Unknown"** for external displays — it now shows the active profile's name.
- **Color Profile recommendations** — *Recommended* now lists the display's own profile (generated by macOS from its EDID) plus sRGB and Display P3, instead of keyword matches that suggested the MacBook's "Color LCD" or the cinema DCI-P3 profile for external monitors.
- **Crash when pressing the brightness keys** on an external display (Swift 6 runtime isolation check on the DDC queue).
- **Brightness keys stopping after a rebuild** — ad-hoc signing changes on every build, so macOS silently dropped the Accessibility grant. See [Local code signing](#local-code-signing).
- **Menu collapsing to zero height** — the scrollable menu content is now sized to fit.

**Improvements**
- **English UI** with a Simplified Chinese translation, using Xcode String Catalogs (`Localizable.xcstrings`, `InfoPlist.xcstrings`).
- **Brightness key permission banner** — the menu shows when Accessibility access is missing, with a button that opens the right settings pane; the app picks up the permission without a restart.
- **"Keep external displays above the built-in display"** is now an opt-in toggle instead of being forced on at first launch.
- **Signing without an Apple developer account** — ad-hoc by default, with an optional local certificate; the original author's team ID is no longer hard-coded.

## What BetterDisplay Features Does This Replace?

| BetterDisplay Feature | FreeDisplay | Notes |
|----------------------|:-----------:|-------|
| DDC Brightness & Contrast | ✅ | Hardware control via IOKit I2C (Intel) / IOAVService (Apple Silicon) |
| Software Brightness (Gamma) | ✅ | Per-display gamma table control with smooth transitions |
| Keyboard Brightness Keys for External Displays | ✅ | Intercepts brightness keys when cursor is on external display, shows native macOS OSD |
| Auto Brightness Sync | ✅ | Syncs external display brightness with built-in display changes |
| HiDPI Virtual Displays | ✅ | Creates HiDPI dummy displays via CGVirtualDisplay private API |
| Display Arrangement | ✅ | Position displays (external above built-in, etc.) |
| Resolution & HiDPI Switching | ✅ | Browse and switch all available display modes including HiDPI |
| ICC Color Profile Management | ✅ | Switch color profiles per display via ColorSync |
| Image Adjustment (Gamma/Temperature) | ✅ | Software contrast, color temperature, RGB channels, invert |
| Display Presets | ✅ | Save & restore full display configurations with one click |
| Virtual Display (Dummy) | ✅ | Create headless virtual displays |
| Notch Management | ✅ | Hide the MacBook notch with a black overlay |
| Launch at Login | ✅ | Via SMAppService |

### Not Included (intentionally)

- Screen streaming / PiP — rarely used, adds complexity
- EDID override — requires SIP disabled
- XDR/HDR extra brightness — requires specific hardware

## Installation

### Option 1: Download DMG

1. Download `FreeDisplay.dmg` from [Releases](https://github.com/yb1997/FreeDisplay/releases/latest)
2. Open the DMG and drag **FreeDisplay.app** to **Applications**
3. Open FreeDisplay. macOS will say it can't verify the developer, because the app isn't notarized (that needs a paid Apple Developer account). Click **Done**, then go to **System Settings → Privacy & Security**, scroll down and click **Open Anyway**. This is needed only once.

   Or, from Terminal: `xattr -dr com.apple.quarantine /Applications/FreeDisplay.app`
4. Grant **Accessibility** when asked, so the brightness keys work on external displays. Updates keep this permission.

### Option 2: Build from Source

```bash
brew install xcodegen
git clone https://github.com/yb1997/FreeDisplay.git
cd FreeDisplay
xcodegen generate
xcodebuild -scheme FreeDisplay -configuration Release build
```

### Local code signing

Builds are ad-hoc signed by default, so no Apple developer account is needed. Ad-hoc signatures change on every build, which makes macOS forget the Accessibility permission the brightness keys need. To keep it across rebuilds:

1. Open **Keychain Access → Certificate Assistant → Create a Certificate…**, name it `FreeDisplay Local`, and set **Certificate Type** to **Code Signing**.
2. `cp Config/Signing.local.xcconfig.example Config/Signing.local.xcconfig` (this file is gitignored).
3. Rebuild, then grant Accessibility to the new build once.

Releases (`./scripts/release.sh vX.Y.Z`) are signed with the same certificate, which is what lets users keep the Accessibility permission across updates. Keep a backup of it (Keychain Access → right-click the certificate → **Export** as `.p12`): signing a release with a different certificate makes every user grant Accessibility again.

## Tech Stack

- **Swift 6** + **SwiftUI** (MenuBarExtra)
- **IOKit** — DDC/CI I2C for hardware brightness/contrast
- **CoreGraphics** — Display enumeration, resolution, arrangement
- **ColorSync** — ICC color profile management
- **CGVirtualDisplay** — Virtual display creation (private API, macOS 14+)
- **CoreDisplay** — Built-in display brightness reading (private API, via dlopen)
- Zero third-party dependencies

## How It Works

FreeDisplay sits in your menu bar and talks directly to your displays:

- **External monitors**: Uses DDC/CI protocol over I2C (Intel) or IOAVService (Apple Silicon) to control hardware brightness, contrast, and other settings
- **Built-in display**: Uses CoreGraphics gamma tables for software brightness adjustment
- **Brightness keys**: Installs a CGEventTap to intercept keyboard brightness keys and route them to the display under your mouse cursor
- **Auto brightness**: Polls the built-in display brightness via CoreDisplay private API and proportionally adjusts external displays
- **HiDPI**: Creates virtual displays via CGVirtualDisplay private API, or writes display override plists for persistent HiDPI
